# 绍兴滨海新区国投集团农田数字化管理系统

## 1. 文档定位与设计原则

### 1.1 文档定位

本文件将招标文件中的建设内容转化为可落地的系统需求和设计方案，覆盖：

- 业务需求与建设目标；
- 软件平台功能；
- GIS 农田一张图；
- 无人机低空巡检；
- 视频监控；
- 智能电表监管；
- 应急语音播报；
- 云资源、网络和安全；
- 实施、调试、验收和三年运维；
- 15 分钟演示视频的重点功能。

### 1.2 设计原则

1. **一张图统领业务**：农户、合同、地块、作物、设备、告警和视频必须形成空间关联。
2. **数据驱动管理**：将“人找数据”转为“系统推送异常、主动提醒责任人”。
3. **先闭环、再扩展**：先确保档案—地块—合同—预警—处置主链路稳定，再扩展无人机、广播、溯源等能力。
4. **软硬件一体化**：设备接入、平台展示、事件告警和运维管理统一设计，避免形成孤岛。
5. **演示与交付一致**：演示数据模型、页面结构和实际交付系统保持一致，避免只做展示原型。
6. **安全可审计**：所有重要数据和操作保留来源、时间、人员、状态和处理记录。

## 2. 项目背景、目标与范围

### 2.1 项目背景

项目区由云禾农旅管理，土地规模约 1.8 万亩。现有管理存在农田底数分散、流转主体信息难查、合同到期及履约风险不易提前发现、田间设备和视频分散、夜间违规行为依赖人工巡查、极端天气响应不及时等问题。

招标文件要求运用大数据、物联网、无人机、智能监控等技术，建立高效实用的农田数字化管理系统，实现农田管理数字化、监管主动化、服务精准化。

### 2.2 建设目标

| 目标 | 目标说明 | 可验证结果 |
|---|---|---|
| 掌握农田底数 | 统一管理农户、地块、合同、作物等基础数据 | 可按户、地块、区域查询和统计 |
| 以图管地 | 建设 GIS 农田一张图 | 点击图斑可查看完整关联信息 |
| 合同风险前置 | 对履约、到期、欠费进行主动预警 | 三色预警、统计、提醒、留痕 |
| 监管主动化 | 接入无人机、视频、气象和电表数据 | 异常事件进入统一告警中心 |
| 提高响应效率 | 支持告警确认、处置、关闭和复盘 | 形成事件处理闭环 |
| 支撑安全生产 | 通过广播、视频、气象预警快速响应 | 支持远程喊话和预警播报 |
| 保障长期运行 | 完成云资源、安全、等保和三年运维 | 系统可用、可管、可追溯 |

## 3. 用户角色与权限设计

### 3.1 用户角色

| 角色 | 典型使用场景 | 核心权限 |
|---|---|---|
| 集团/业主领导 | 查看总体态势、风险和经营指标 | 驾驶舱、统计、告警和只读查询 |
| 农业项目管理人员 | 管理农户、合同、地块、作物 | 档案、合同、地图、统计、导入导出 |
| 片区/基地负责人 | 查看所属区域和处理告警 | 区域数据、视频、告警处置、广播 |
| 巡检人员 | 执行巡检、核查现场 | 巡检任务、事件、图片、视频、处置反馈 |
| 财务/合同人员 | 管理合同收缴和履约状态 | 合同、金额、租金、到期、报表 |
| 设备运维人员 | 维护摄像头、无人机、广播和云资源 | 设备状态、远程运维、日志、工单 |
| 系统管理员 | 用户、角色、参数和字典管理 | 全部系统配置权限 |
| 只读/领导账号 | 汇报、查看和大屏展示 | 只读权限，禁止修改数据 |

### 3.2 权限模型

采用“角色权限 + 数据范围 + 操作审计”的组合模型：

- 菜单权限：控制可以进入的模块；
- 按钮权限：控制新增、编辑、删除、导入、导出、预警配置等操作；
- 数据范围：按集团、基地、片区、行政区域、地块和责任人限制数据；
- 设备权限：限制某类用户访问指定摄像头、无人机和广播区域；
- 资源权限：限制图片、视频、合同扫描件的查看和下载；
- 审计权限：管理员可查看登录、数据变更、告警处置和设备控制日志。

## 4. 业务需求分析

### 4.1 流转大户“一户一档”

#### 4.1.1 业务目标

将流转主体从分散表格转为标准化档案，支撑合同、地块、作物、设备和告警的关联查询。

#### 4.1.2 业务流程

1. 新增或批量导入流转大户；
2. 校验姓名、联系方式、行政区域和合同编号等必填字段；
3. 关联一个或多个流转合同及地块；
4. 维护当期种植作物和经营主体性质；
5. 在档案详情中查看合同、地块、视频、电表、告警和历史记录；
6. 支持按区域、作物、合同状态、面积区间组合筛选；
7. 导出统计结果和档案明细。

#### 4.1.3 功能设计

| 功能 | 详细要求 | 优先级 |
|---|---|---:|
| 档案列表 | 分页、排序、模糊搜索、状态展示、批量操作 | P0 |
| 档案新增/编辑 | 姓名、联系方式、行政区域、经营主体性质等 | P0 |
| 合同关联 | 关联合同编号、签订/到期时间、金额和履约状态 | P0 |
| 地块关联 | 关联地块编号、面积、位置和种植作物 | P0 |
| Excel 导入 | 模板下载、批量导入、错误行反馈、重复校验 | P0 |
| Excel 导出 | 按当前筛选条件导出，保留统计口径 | P0 |
| 档案详情 | 汇总展示合同、地块、作物、设备和事件 | P0 |
| 操作留痕 | 新增、修改、导入、导出和删除记录 | P1 |

**【演示重点】**：必须完整展示“下载模板/准备文件—Excel 导入—档案生成—打开详情—导出”的闭环。演示数据至少包含正常、即将到期和已到期三类合同状态。

### 4.2 农田一张图

#### 4.2.1 业务目标

将地块图斑作为业务主索引，形成“以图管地、以地管人”的统一入口。

#### 4.2.2 地图能力

- 加载项目区底图和农田图斑；
- 按地块编号、农户姓名、作物名称定位；
- 图斑按合同状态、用电状态、告警等级、作物类别分层着色；
- 点击图斑弹出农户、合同、作物、面积、设备和告警信息；
- 从农户档案反向定位地块；
- 从合同预警、无人机告警、视频设备反向定位地图；
- 支持图层开关、图例、缩放、全屏和基础量测；
- 支持基地介绍和项目区概况展示。

#### 4.2.3 地图设计

地图页面建议采用“左侧筛选/图层—中间地图—右侧详情”的结构：

- 左侧：区域、农户、地块、作物、合同、告警筛选；
- 中间：农田图斑、设备点位、告警点位、视频点位；
- 右侧：选中地块的基本信息、合同卡片、关联设备和事件列表；
- 顶部：总户数、总面积、主栽作物、合同风险和告警数量；
- 底部或抽屉：视频、抓拍图片和事件处置记录。

**【演示重点】**：必须展示“搜索农户/地块—地图自动定位—点击图斑—查看农户/合同/作物—打开关联视频或告警”的连续联动，不能只展示静态地图。

### 4.3 合同全生命周期监管

#### 4.3.1 管理范围

- 合同基本信息；
- 合同原件扫描件上传和在线预览；
- 合同关联农户和地块；
- 合同履约进度；
- 租金总额、已纳金额、待缴金额；
- 未缴租金等履约异常；
- 合同履约中、即将到期、已到期状态；
- 到期预警配置、查询、统计和提醒。

#### 4.3.2 三色预警规则

| 颜色 | 默认规则 | 系统动作 |
|---|---|---|
| 绿色 | 剩余有效期大于 90 天且正常履约 | 正常展示，不产生高优先级告警 |
| 黄色 | 剩余有效期不超过 90 天且大于 30 天 | 到期提醒，进入待跟进清单 |
| 红色 | 剩余有效期不超过 30 天或已逾期 | 高危预警，推送负责人并要求处置 |

阈值必须支持后台配置，预警结果同步至驾驶舱和农田一张图，并支持按等级、区域、时间查询。

**【演示重点】**：演示至少三条不同状态的合同，修改或预置到期日期后展示颜色变化、统计变化、地图联动和详情查看。

### 4.4 智能电表缴费监管

#### 4.4.1 业务目标

对接农户智能电表系统，以余额、欠费和断电状态判断用电风险，减少人工催缴。

#### 4.4.2 三色规则

| 颜色 | 默认规则 | 处置建议 |
|---|---|---|
| 绿色 | 余额充足、无欠费 | 正常用电 |
| 黄色 | 余额不高于 30 元或预计 7 天内欠费 | 催缴提醒 |
| 红色 | 已欠费并触发断电 | 高危告警、重点处理 |

#### 4.4.3 功能设计

- 电表点位和农户/地块关联；
- 实时或定时同步余额、用电量、欠费和断电状态；
- 状态三色展示；
- 正常、催缴中、已断电户数及占比统计；
- 地图图斑联动展示；
- 接口失败、数据超时和异常值告警；
- 支持预警阈值配置和数据导出。

**【演示重点】**：建议作为综合能力展示，至少演示一个黄色催缴和一个红色断电样例，并体现地图和驾驶舱数量同步变化。

### 4.5 无人机巡检监管

#### 4.5.1 业务目标

通过机巢式无人机和飞控平台，对项目区开展自动巡航和夜间巡检，接入渣土倾倒 AI 识别结果。

#### 4.5.2 飞控和巡检能力

- 虚拟座舱远程控制；
- 多机操控、智能跟踪、指点飞行；
- 设备状态、任务进度、飞行统计看板；
- 目标标记、航线规划、作业区域分配；
- 单机或多机同屏直播；
- 航点、巡逻、面状、带状、贴近摄影、斜面和几何体航线；
- 机载/云端 AI 检测和自动巡逻；
- 云端二维、三维实景或点云建模；
- PDF、DXF 等文件导入和历史影像回溯；
- 点线面、坐标、高度、长度、面积、体积、坡度和断面量测；
- 两期影像变化检测和报告生成；
- 禁飞区、作业区、禁降区配置；
- 飞行数据报送、飞行日志、飞行报告导出；
- 大雨、大风等极端天气提醒；
- 远程查看机场和无人机状态、远程调试；
- 文件同步、直播转发、飞行状态和事件通知接口。

#### 4.5.3 渣土告警闭环

1. 无人机执行夜间巡检任务；
2. AI 识别渣土倾倒行为；
3. 生成告警位置、时间、抓拍图片和识别结果；
4. 告警进入统一告警中心和驾驶舱；
5. 地图标注告警区域；
6. 管理人员查看图片并确认/驳回/转派；
7. 形成处置记录和统计报表。

渣土区域三色规则：未发生为绿色，每周发生 1 次及以上为黄色，发生超过 3 次为红色。

**【演示重点】**：这是视频评分重点之一。必须展示时间统计、地图告警点、现场抓拍图片放大预览和三色区域分布，不能只打开无人机飞控平台首页。

### 4.6 视频监控实时管理

#### 4.6.1 设备接入

- 统一接入项目区现有海康视频监控设备；
- 支持 25 台新增 4G 网络球机；
- 视频流稳定传输；
- 支持 H.265/H.264/MJPEG 等视频编码；
- 支持 1080P 及以上主码流展示；
- 支持云台、变倍、预置位和必要的远程控制；
- 支持设备在线、离线、信号和存储状态监测。

#### 4.6.2 地图联动

- 摄像头点位与地块、农户、区域关联；
- 点击地块自动加载对应摄像头；
- 支持同一地块关联多个摄像头；
- 支持按农户或地块检索关联实时画面；
- 支持实时视频、抓拍、录像回放或平台跳转，具体以现有平台能力为准；
- 视频异常时展示明确的失败原因和重连操作。

**【演示重点】**：应从农户或地图图斑进入视频，而不是单独打开视频列表，证明“地块—农户—视频”的关联关系真实存在。

### 4.7 防汛防台预警

- 接入气象灾害预警信息；
- 展示台风、暴雨、洪水、大风等风险类型；
- 驾驶舱显示风险等级、影响区域、发布时间和有效期；
- 地图展示预警影响范围；
- 支持向责任人推送或联动应急广播；
- 预警到期自动关闭并保留历史记录。

**【演示重点】**：可在视频后用 30 秒展示气象预警卡片，并说明可以联动广播和责任人通知。

### 4.8 农产品溯源

#### 4.8.1 业务目标

以二维码为入口，形成种植、加工、流通和质量安全的全生命周期档案。

#### 4.8.2 功能设计

- 批次/产品档案；
- 地块、农户、作物和种植周期关联；
- 播种、施肥、用药、采收等生产记录；
- 加工、检测、包装和流通信息；
- 二维码生成、打印、扫码查询；
- 溯源信息防篡改和操作日志；
- 异常批次和召回记录。

由于招标文件对溯源数据的具体字段没有展开，建议第一期先完成批次、地块、种植主体、关键农事记录和二维码查询，后续再扩展加工流通字段。

### 4.9 应急语音播报

#### 4.9.1 功能设计

- WEB 和 APP 统一控制；
- 单点、多点、分区和全区广播；
- 文字转语音；
- 电话/短信白名单接入；
- 定时任务和节目管理；
- 终端状态、音量和网络状态查看；
- 预警音乐和紧急插播；
- 火警、台风、洪水、地震等预置预警音频；
- 广播日志、通话日志和操作审计；
- 远程配置升级和节目下发。

#### 4.9.2 设计要求

广播必须与告警中心建立联动规则，例如：

> 红色气象预警/防汛事件 → 生成播报建议 → 管理员确认 → 选择区域 → 语音播报 → 记录操作日志。

涉及实际播报的动作应设置二次确认和权限控制，避免误播。

## 5. 综合驾驶舱设计

### 5.1 首页指标

建议首页集中展示：

- 流转大户总数；
- 农田总面积；
- 当期主栽作物及面积占比；
- 合同正常、黄色、红色数量；
- 正常用电、催缴、断电户数；
- 本周/月/年渣土告警数量；
- 在线/离线摄像头数量；
- 无人机机场和任务状态；
- 当前气象预警；
- 待处理事件数量。

### 5.2 交互设计

- 指标卡片点击进入对应列表；
- 图表点击联动筛选；
- 地图点位点击打开详情抽屉；
- 告警数量实时刷新或按配置定时刷新；
- 页面显示数据更新时间和数据来源；
- 大屏模式隐藏管理操作，仅保留态势展示。

### 5.3 【演示重点】驾驶舱首页

视频开场应直接展示“规模—农户—面积—合同风险—用电风险—巡检告警”的全局态势，随后从指标卡片进入业务详情，证明驾驶舱不是静态大屏，而是系统业务的入口。

## 6. 数据架构设计

### 6.1 核心实体

| 实体 | 关键字段 | 关联实体 |
|---|---|---|
| 流转主体 | 主体 ID、姓名、联系方式、区域、性质 | 合同、地块、作物、电表、告警 |
| 地块 | 地块 ID、图斑、面积、区域、坐标 | 主体、合同、作物、设备 |
| 合同 | 合同编号、签订/到期时间、金额、履约状态 | 主体、地块、缴费、预警 |
| 作物 | 作物类型、种植批次、周期 | 地块、主体、溯源 |
| 电表 | 设备 ID、余额、欠费状态、断电状态 | 主体、地块、预警 |
| 摄像头 | 设备 ID、厂商、流地址、点位、在线状态 | 地块、主体、告警 |
| 无人机任务 | 任务 ID、航线、时间、机场、执行状态 | 设备、媒体、告警 |
| 告警事件 | 类型、等级、位置、时间、图片、状态 | 地块、主体、设备、处置 |
| 气象预警 | 类型、等级、区域、发布时间、有效期 | 地图、广播、处置 |
| 溯源批次 | 批次号、二维码、产品、地块、生产记录 | 主体、作物、流通 |
| 广播任务 | 区域、内容、方式、执行时间、状态 | 告警、终端、日志 |
| 操作日志 | 用户、动作、对象、时间、结果、IP | 全部业务对象 |

### 6.2 关键数据关系

```text
项目区/行政区域
   └─ 地块图斑
       ├─ 流转主体
       │   └─ 流转合同
       │       ├─ 履约/缴费/到期预警
       │       └─ 合同扫描件
       ├─ 作物/种植批次/溯源二维码
       ├─ 摄像头/电表/广播终端
       └─ 无人机巡检/抓拍图片/告警事件
```

### 6.3 数据质量规则

- 地块编号必须唯一；
- 合同编号必须唯一；
- 一个地块可以有历史合同，但同一期间只能有一个有效合同；
- 合同到期日不得早于签订日；
- 面积必须大于 0，且地块面积和合同流转面积口径明确；
- 农户手机号按格式校验，但允许缺失并标记待补全；
- 导入数据必须保留原文件、导入人、导入时间和失败原因；
- 图斑与业务数据关联失败时进入待处理清单，不得静默丢弃；
- 设备离线、接口超时和数据过期要区分显示。

## 7. 系统总体技术架构

### 7.1 分层架构

```text
访问层：PC管理端 / 大屏驾驶舱 / 手机APP / 溯源H5
        ↓
业务层：档案 / 地图 / 合同 / 电表 / 视频 / 无人机 / 气象 / 溯源 / 广播 / 告警
        ↓
平台层：统一认证 / 消息中心 / 文件中心 / GIS服务 / 规则引擎 / 统计分析 / 日志审计
        ↓
数据层：关系数据库 / GIS空间数据 / 时序数据 / 文件与图片 / 视频流 / 日志库
        ↓
接入层：海康设备 / 智能电表 / 无人机平台 / 气象接口 / 广播终端 / 大屏 / Excel
        ↓
基础设施：云服务器 / 云数据库 / 云存储 / 负载均衡 / 专线 / SSL / 安全防护
```

### 7.2 推荐部署方式

- 前端应用通过 HTTPS 访问；
- 业务服务与数据库分离部署；
- 视频流和大文件走对象存储/媒体服务，不直接占用业务数据库；
- 无人机、视频、电表、气象和广播采用适配器服务接入；
- 对外接口统一经过 API 网关和鉴权；
- 通过消息队列或事件总线处理告警、推送和广播联动；
- 数据库、文件和配置分别备份；
- 云资源按招标文件提供的服务器、数据库、带宽、域名、SSL 和负载均衡配置实施。

### 7.3 接口设计原则

每个外部系统都应形成一份接口说明，至少包含：

- 接口名称、方向、协议、地址和鉴权；
- 请求/响应字段、编码和时间格式；
- 数据唯一标识和关联规则；
- 调用频率、超时、重试和限流；
- 错误码、异常记录和人工补偿；
- 数据更新时间和历史补传机制；
- 脱敏、加密和访问审计。

## 8. 非功能需求

### 8.1 性能

- 常用列表查询在正常数据量下应快速返回；
- 地图首次加载和图层切换应避免长时间白屏；
- 驾驶舱指标应显示数据更新时间；
- 视频加载失败应有重连和错误提示；
- 大批量 Excel 导入采用异步任务，提供进度和结果下载；
- 统计报表导出不得阻塞前端页面。

### 8.2 可用性

- 核心页面支持主流桌面浏览器；
- 大屏支持 16:9 分辨率；
- 颜色不能作为唯一状态表达，应同时展示文字和图标；
- 空数据、接口异常、无权限和设备离线要有明确提示；
- 关键操作如删除、广播、远程控制必须二次确认。

### 8.3 安全

- 账号密码、权限、会话超时和登录失败控制；
- 重要数据传输使用 HTTPS；
- 合同扫描件、图片和视频按权限访问；
- 重要操作和远程控制全量留痕；
- 数据库、文件和日志定期备份；
- 服务器、应用、数据库和网络边界按等保二级要求整改；
- 完成网安备案及二级等保测评配合工作。

### 8.4 运维

- 设备、服务、接口、数据库、存储和证书统一监测；
- 提供故障、告警、工单和巡检记录；
- 提供三年免费维护，包括软件、云资源协同、设备巡检和问题处理；
- 关键设备支持远程查看状态；
- 摄像头和广播设备按现场计划提供移位、安装和维护服务。

## 10. 视频演示设计结论

### 10.1 必须演示的 P0 功能

3. 农户/地块搜索与地图定位；

- 地块关联实时视频；
- 智能电表催缴和断电状态；
- 无人机任务/直播/设备状态；
- 气象预警；
